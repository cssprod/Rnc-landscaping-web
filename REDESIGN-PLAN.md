# RNC redesign plan (Cedar Springs blueprint, v2)

This is the working brief for the redesign. The source of every requirement is `research/cedar-springs-teardown-blueprint.md` (the "blueprint"; section numbers below refer to it). Read the blueprint, `CONTRACT.md` and this file before changing anything. The goal: Cedar Springs-grade art direction (editorial layout, large photography, project spec strips, a named process) on top of RNC's fast, accessible static build, fixing every Cedar Springs fault the blueprint lists (A13 #1–36) and delivering the full RNC blueprint (C1–C8 and the P0–P4 checklist).

## Already done (foundation commit)
- `content/site.json` is the single source of truth (NAP, hours, credentials, services, municipalities); `site/site.config.mjs` reads it. New tokens: `[REPLY TIME]`, `[GOOGLE PROFILE]` (reviews link), `[FOUNDED]` (optional, JSON-LD only).
- New IA (C1): `/projects/` and `/projects/{slug}/` replace `/portfolio/*`; `/free-quote/` replaces `/quote/`; new `/process/`. Old URLs 301 via `site/src/pages/redirects.mjs` → `dist/_redirects`. Content links already updated.
- Routes split by page family: `site/src/pages/{home,services,projects,areas,company,resources,quote,legal}.mjs` (+ `_shared.mjs`, `routes.mjs` aggregator). Each route can declare `sources` (repo paths) → sitemap `<lastmod>` from git commit dates.
- `site/src/styles/*.css` are concatenated in file-name order (old stylesheet is `50-legacy.css`, to be replaced). Every `site/src/scripts/*.js` becomes its own hashed module; `main.js` loads everywhere, others via `layout(env, { scripts: ['quote'] })`.
- Head metadata and JSON-LD live in `site/src/lib/seo.mjs` (`headMeta`, `jsonLd`); `layout.mjs` only calls them.
- `node build.mjs --out=DIR` builds elsewhere; tools read `SITE_DIST=DIR`. Use your own out dir when working in parallel; never build into another agent's dir.

## Decisions (do not relitigate)
- Keep **13** municipalities (the blueprint's "12" is a miscount; Highlands is included) and the contract's service slugs (`tree-vegetation`, not `tree-vegetation-management`).
- Keep `/commercial/` (commercial proof points, A12 #5), `/resources/` (seasonal guides), `/reviews/`, `/contact/` in addition to C1. No careers page.
- Primary nav (C1): Services ▾ · Projects · Service areas ▾ · Process · About · [Call] [Free quote]. Disclosure `<button aria-expanded>` menus, never `href="#"`. Commercial sits in the Services menu; Resources, Reviews, FAQ, Contact in the footer.
- **Quote builder (C5), one page, six inputs**: services (4 large multi-select cards), municipality (`<select>` of 13, prefilled from `?area=`; `?service=` prefills services), description textarea with example prompts, timing (ASAP / this season / planning ahead), name, "best way to reach you" (Reply by email / Call me / Text me; a phone field appears and becomes required for call or text). The request is sent from the visitor's own email app, so their address is already known: no email field. Submit builds a `mailto:` (subject "Free quote request — Irrigation — Saanich", body ≤ ~1,800 chars in the URL; if longer, truncate in the URL and tell them to paste the copied full text). Form `action` is the mailto (`method="post" enctype="text/plain"`) for no-JS. After submit: in-page panel with Copy request (Clipboard API, `role="status"` confirmation), the address with a copy button, Call / Text us (`tel:`/`sms:` with short prefilled body, only when PHONE is known), Gmail / Outlook web compose links. Native validation + inline errors (`aria-describedby`) + error summary at top; never clear values; draft in `sessionStorage`. Plausible events (no personal data): `quote_started`, `quote_mailto_opened` {service, area}, `quote_copied`, `quote_webmail_opened` {provider}, `call_click` {location}, `sms_click` {location}, `email_click` {location}, `capability_statement_downloaded`. Pure builders exported from `site/src/scripts/quote.js` and unit-tested with `node --test site/tests/unit/` (encoding, length cap, subject format).
- **Schema (C6)**: one `@graph` per page with `@id`s: `HomeAndConstructionBusiness` (the current `LandscapingBusiness` is not a schema.org type — fix it), `WebSite`, `WebPage`, `Service` per service page, `BreadcrumbList`, `FAQPage` (semantic only), `Article` with author for guides. `areaServed` = 13 places, `hasOfferCatalog` = 4 services, `openingHoursSpecification` from `site.json.openingHours` when set. Placeholders are omitted, never published. **No** `Review` / `AggregateRating`.
- **OG**: `og:locale` en_CA, `og:type` website (article for guides), one OG image per page: a dev tool (`site/tools/og-cards.mjs`, Playwright) renders 1200×630 JPEG title cards into `site/static/og/` (committed; build falls back to the page photo, warns if a card is missing or stale).
- **Focus contrast (C3, P0 #3)**: light-mode Camas `#5A4FCF` is 2.8:1 on Fir night `#0B1F15` (footer, CTA and other deep bands): add a focus token for deep/photo surfaces (≥ 3:1, e.g. a Camas tint) and make `brand/check-contrast.mjs` test every focus/background pairing in both appearances.
- **Design direction (C3)**: editorial, not "glass everywhere". Large real photography, generous white space, fluid type scale (display 2.5→4.5rem, h1 2.0→3.25, h2 1.5→2.25, h3 1.25→1.5, body 1.0625→1.125 / 1.6, 65ch measure, small 0.875; Inter 400/600/700; Newsreader italic only in quotes), two-tone discipline (Basalt ink `#0E1611` on Sea fog `#F4F6F2`), Douglas fir primary. Liquid Glass **only on chrome** (header, sticky bar, menus, CTA panels over photos); content cards are solid Sea fog / white. Remove aurora washes, pointer-following sheen and tilt. RNC's own signature (so it is not a Cedar Springs copy): a field-survey "spec sheet" strip (hairline rules, tabular figures, sentence-case labels), numbered sections, and a subtle topographic contour motif drawn from the area map. Sentence case in source HTML (no lowercase-in-source, no all-caps). Motion 150–250 ms opacity/transform only, same-document View Transitions where supported (project filter, before/after toggle), everything off under `prefers-reduced-motion`; no loaders, sliders, autoplay or scroll-jacking.
- **Responsive (C4)**: one DOM per component (never mobile and desktop copies); breakpoints 40em / 64em / 80em; container queries for cards and tiles. Mobile sheet nav: `inert` background, Esc closes, focus returns, Services and Areas as accordions. Sticky action bar below 1024 px: Call (`tel:`; "Contact" → `/contact/` until PHONE is known) + Free quote, each ≥ 48 px, `env(safe-area-inset-bottom)`, hidden while the quote form is in view or the on-screen keyboard is open. `scroll-padding-top/bottom` = header/bar heights (2.4.11). Targets ≥ 44×44 for primary controls, ≥ 24×24 for everything else. No horizontal scroll at 320 px; 200% zoom works.
- **Images (C4, P4 #17)**: `<picture>` AVIF → WebP → JPEG at 480/768/1024/1600 for local photos. `site/tools/process-images.mjs` (uses `sharp` installed into a scratch dir, not a repo dependency) turns `media/photos/<slot>.(jpg|png)` into `site/static/img/<slot>-<w>.<fmt>` plus a `media/photos.json` manifest (dims, licence), stripping all metadata (EXIF GPS). Stock CDN photos remain labelled placeholders (Unsplash is blocked in this container: use `--offline-images` for screenshots and tests). Hero `fetchpriority="high"`, never lazy; everything else `loading="lazy" decoding="async"`; explicit width/height. Alt text written by hand; `alt=""` for decorative images.
- **Municipality pages (C2, C6)**: every page needs ≥ 3 genuinely local blocks: (1) "Local rules that affect your yard" with source links and a last-reviewed date (`research/areas.json` facts were checked 2026-11-19), (2) local conditions (exposure, soils, deer, salt spray, wells vs regional water, lot types), (3) local proof (projects in that municipality or anonymised job notes, labelled Sample). Plus most-requested services and why, neighbouring municipalities, CTA to `/free-quote/?area=<slug>`. Must pass the swap test. Never invent facts about RNC; municipal facts carry `verify: true` and a source.
- **Projects (A12 #1)**: spec strip = municipality, service, season, duration, scope tags (and plant palette where relevant); Challenge → Approach → Result; **no budgets**. Keep every sample labelled.
- **Guides (A13 #20)**: byline "[OWNER NAME], RNC Landscaping" linking to `/about/`; keep the real dates (do not invent dates); show published and updated dates in one format ("19 November 2026").
- **Trust (C5)**: reply-time promise (`[REPLY TIME]`), "What happens next" steps, credentials row with tokens only, reviews band (3 quotes, Newsreader italic, attribution as role + municipality for samples, "Read all reviews on Google" → `[GOOGLE PROFILE]`), named owner, local-rules expertise, a plain-language workmanship guarantee built around `[WARRANTY]`.

## Phases
1. **Foundations in parallel**: design system + chrome; content (areas); content (projects, pages, services, guides); quote builder; SEO. The design-system stream also publishes the component primitives every page uses (section head, eyebrow/index, spec strip, project card, review quote, CTA band, FAQ `<details>`, local-rules callout, credential row, breadcrumb) and documents their markup in `site/COMPONENTS.md`.
2. **Templates in parallel** (C2): home; services hub + service page (sticky in-page TOC on desktop, "What's included", "Good fit if…", seasonal timeline, process, related projects, local-rules callout, 5–6 FAQs); areas hub (SVG map + list) + municipality page; projects portfolio (filter service × municipality, no-JS shows all) + case study (accessible before/after with keyboard and a side-by-side toggle); company pages (process with maintenance and installation tracks, about, FAQ, commercial, reviews, contact), guides, legal, accessibility statement (WCAG 2.2 AA, voluntary under the Accessible BC Act), helpful 404.
3. **Integrate and verify**: build checks (`check-seo.mjs`: duplicate titles, exactly one H1, title ≤ 60 / description ≤ 160, filename-like alt text, double-encoded entities, `href="#"`, slug lint, `lang="en-CA"`, canonical, repeated paragraph text inside `<main>`, typo list, banned brand-voice words); Playwright at 320/390/768/1024/1440 in light and dark (no horizontal overflow, keyboard paths, focus never obscured by the sticky header/bar, menus, quote builder with and without JS); axe (0 violations); Lighthouse CI budgets (C7: ≥ 95 in all four categories on every template; CSS ≤ 40 KB, JS ≤ 25 KB, fonts ≤ 110 KB, home ≤ 500 KB, inner ≤ 350 KB transferred; 1 third-party origin besides placeholder photos); then an adversarial blueprint-compliance audit (every A13 fault and P0–P4 item → evidence or a fix) and a visual critique of screenshots; loop until clean.
4. **Docs**: update `README.md`, `CONTRACT.md`, `site/README.md`, `site/CHANGELOG.md`, `site/LAUNCH-CHECKLIST.md`, `brand/brand.md`; add `TRACEABILITY.md` mapping every blueprint item to where it is implemented (or why not, e.g. GBP setup is off-site work for RNC).
